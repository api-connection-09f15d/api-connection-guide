网页会员与 API 凭据先分开

先确认当前使用的是网页账户、桌面应用还是开发接口。网页已登录不意味着 API 请求已携带正确凭据；网络套餐也不包含 AI 平台会员或接口额度。到目标平台自己的账户或控制台核对，不向代理服务商提供 API 密钥求证余额。

API 调用还需核对应用所配置的真实服务地址、模型或功能权限及计费项目。不要把网页登录密码填入 API 密钥栏，也不要把私人订阅地址当成接口地址。使用第三方中转时，先了解数据接收方和权限范围，不凭“能返回结果”推定其身份可信。

用最小请求区分失败阶段

先用一条不含私人内容的短文本执行一次小任务，记录时间与完整错误类别，避免带大附件或长上下文。如果这个请求也无法建立连接，就优先核对该程序是否使用了代理、目标地址是否正确，以及连接日志有无对应目标。

网页端与命令行程序可能使用不同代理设置。只在网页可用、程序连接失败时，按该程序文档核对其网络配置，不因为系统代理已经开启就认为所有请求都经过同一路径。不要在公开命令示例或截图中保留真实密钥。

如果短文本成功，而长请求或上传失败，先转入功能层排查，不立即更换全部网络设置。记录失败是否发生在提交前、上传中、等待响应时或任务已创建后。

状态码只是线索，不是完整原因

401 通常需要检查有效认证凭据，403 表示服务器拒绝处理，429 表示请求过多；具体业务条件以该平台返回的脱敏错误类型为准。不要把每个429都写成余额不足，也不要把每个403都写成代理节点被封。

收到明确错误后，先查看平台控制台中的请求记录、权限或限制说明，再按其建议处理。若返回等待提示，暂停重试；未知错误时保留请求标识，交给平台支持定位。凭据有误应在自己的应用安全设置中修正，不把密钥发到公开 Issue。

长时间没有响应不代表服务端没有执行。对于会产生任务或费用的操作，先查询现有任务状态或请求记录。只有平台文档支持相应重试机制时才按其流程使用，不假设所有 API 都能安全重复提交。

上传失败按文件与任务分别处理

先检查平台当前允许的格式、大小和账户权限。把文件换成一份不含私人信息的小样本，在相同网络与应用中做一次对照。小文件成功而原文件失败时，再检查原文件大小、内容编码、密码保护或具体格式要求；这还不能单独证明只是文件过大。

如果上传进度结束后才报错，记录错误发生在解析、索引还是实际任务执行阶段。不要把“上传完成”当成“处理成功”，也不要反复上传同一份敏感材料。查看任务列表，确认是否已有重复项目需要按平台正常流程管理。

若连小样本都在传输阶段中断，保留文件大小、失败时间和应用错误，再比较同一文件在另一个有权使用网络上的结果。一次只改网络，其他条件不动。数据涉及工作秘密时，先确认组织允许该上传目标，不能拿真实材料作为公开复现附件。

保留证据、避免泄露和重复消耗

有效反馈包括：网页或 API、应用版本、请求功能、时间与时区、状态码和脱敏业务错误、是否已有任务、一次小样本对照。隐藏 Authorization、Cookie、带签名的 URL、私人文本、文件内容和完整订阅。
